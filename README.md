# Turbo Kart Arena

海辺の **Sun Cove Circuit（サンコーブ・サーキット）** を舞台にした、PCブラウザ用のオリジナル3Dカートレースです。プレイヤー1台とCPU 3台で、3周の順位を競います。1周の目安は約50〜60秒です。

モデル、コース、看板、UI、アイテム、効果音は、このプロジェクト内で生成しています。任天堂作品のキャラクター・名称・コース・画像・音源などは使用していません。外部API、アカウント、APIキー、外部3Dモデル、外部フォント、音源のダウンロードは不要です。

## 起動

Node.js **22.18以上（24 LTS推奨）** とnpm、WebGL 2が利用できるChrome / Edgeが必要です。

```bash
npm install
npm run dev
```

ターミナルに表示されるURL（通常 `http://127.0.0.1:5173`）を開き、難易度を選んで **START RACE** を押してください。音は開始ボタンを押した後に有効になります。左下のスライダーで音量を変更でき、設定はブラウザに保存されます。

```bash
npm run build     # TypeScript検査と本番ビルド
npm run preview   # distのプレビュー
npm test          # 実ブラウザでの統合テスト
```

初回のnpmインストールにはインターネット接続が必要です。ゲーム実行時に外部サービスへアクセスしません。配布対象は `dist/` です。HTMLを直接ダブルクリックせず、HTTPサーバー経由で開いてください。サブパスへの配布には `vite.config.ts` の `base` を設定します。

## 操作

| キー                 | 操作                                 |
| -------------------- | ------------------------------------ |
| W / ↑                | アクセル                             |
| S / ↓                | ブレーキ。停止後はバック             |
| A D / ← →            | 左右ステアリング                     |
| Space ＋ 左右        | ドリフト                             |
| Space を離す         | 蓄積したミニターボを発動             |
| 左右どちらかの Shift | アイテム使用                         |
| R                    | 最後に通過したチェックポイントへ復帰 |
| Esc                  | ポーズ / 再開                        |

カーブに入る前に少し減速し、Spaceを押しながら曲がってみてください。ドリフトが **0.65 / 1.4 / 2.3秒** 続くと、火花と右下のゲージが3段階に変化します。Spaceを離すと、段階に応じたブーストが発動します。ジャンプ台は速度を乗せて中央付近を通過します。空中でも左右で少し姿勢を調整できます。

画面左上が順位、中央上がラップタイムとベスト、右上がラップとミニマップ、左下がアイテム、右下が速度です。ウィンドウがフォーカスを失ったときは自動でポーズします。

## 実装済み

- 高低差、直線、緩いカーブ、ヘアピン、S字、ジャンプ台、トンネルのある約1.22kmのコース。
- スタートゲート、縁石、ガードレール、芝生、海、木、看板、建物、観客席、タイヤバリア。
- 車体、4輪、シート、ハンドル、前後バンパー、ドライバーをプリミティブで生成。ホイール回転と前輪の操舵。
- 加減速、慣性、グリップ、ドリフト横滑り、高速時の操舵抑制、芝生の減速、ガードレール接触処理。
- 3段階ミニターボ、ジャンプ、重力、着地サスペンション。コースから大きく外れると落下し、約2秒でチェックポイントへ復帰。
- クリスタル型アイテムボックスは取得後5秒で復活。1個だけ保持できます。
- **Turbo**：2.5秒の加速。**Missile**：前方の他車を追尾する弾。**Mine**：後方に設置し、最大18秒残る障害物。**Shield**：6秒間、または攻撃を1回防ぐまで有効。
- CPU 3台はウェイポイントを参照し、走行ラインを変え、前方車を避け、カーブで減速します。CPUもアイテムを取得・使用します。
- Easy / Normal / Hard。CPUごとの速度差。
- 3・2・1・GO!、24個の順序付きチェックポイント、3周判定、逆走表示、順位、ラップ別タイム、リザルト、再レース。
- 滑らかなチェイスカメラ、速度による距離・FOV変化、ドリフト時の横振り。
- タイヤスモーク、3色の火花、ブースト、アイテム取得、命中、着地パーティクル、速度線。
- Web Audio APIで生成したエンジン音、カウントダウン音、アイテム音、ブースト音、命中音。音量保存。
- 画面のリサイズ、狭いウィンドウに対応したUI。操作はPCキーボード向けです。

## 構成

```text
src/
  main.ts                   起動・WebGLエラー時の案内
  config.ts                 タイトル、コース名、周回数、速度、難易度
  style.css                 タイトル、HUD、ポーズ、リザルト
  game/
    Game.ts                 シーン、ライト、ゲームループ、各システムの連携
    RaceManager.ts          状態遷移、チェックポイント、順位、タイム、復帰
  kart/
    Kart.ts                 モデル、車両挙動、ドリフト、ブースト、ジャンプ
    PlayerKart.ts           キーボードを車両入力へ変換
    AIKart.ts               ウェイポイント操舵・ライン選択・速度調整
  track/
    Track.ts                路面、地形、装飾、静的メッシュの結合
    WaypointSystem.ts       閉曲線、距離に対応したサンプル、最近傍探索
  items/
    ItemBox.ts              クリスタルの描画・復活
    ItemManager.ts          取得、発射、追尾、命中、防御
  effects/ParticleSystem.ts  上限360個の再利用パーティクル
  camera/ChaseCamera.ts      追従とFOV
  ui/GameUI.ts              メニュー、HUD、ミニマップ、結果
  audio/AudioManager.ts     音源生成と音量
  utils/                    キーボード入力、プリミティブ生成
tests/
  phase.mjs                 各Phaseの起動・例外チェック
  smoke.mjs                 キー操作・レース・アイテムの統合テスト
  diagnose.mjs              自動走行の詳細診断
```

ゲーム名・画面上のタイトルの各行・コース名・難易度別係数は `src/config.ts` で変更できます。コース形状は `WaypointSystem.ts` の制御点、装飾は `Track.ts`、アイテム時間や威力は `ItemManager.ts` で調整します。

## 検証と設計

Phase 1〜9を順に実装し、それぞれでTypeScript検査、本番ビルド、Chrome起動時の例外確認を実施しました。

`npm test` はインストール済みのChromeを使います。Viteが起動していなければテストが起動します。Edgeで実行する場合はPowerShellで次のように指定できます。

```powershell
$env:BROWSER_CHANNEL = 'msedge'
npm test
Remove-Item Env:BROWSER_CHANNEL
```

テストは実際のキーボード入力と描画に加え、固定刻みの物理シミュレーションで3周を走行します。完走テスト中のプレイヤーはテスト専用の操舵計算で運転し、位置や周回カウンターを直接書き換えて完走させていません。能力単体・逆走防止・落下などのテストでは、検証条件を作るため位置や所持アイテムを設定します。結果とスクリーンショットは `test-results/` に保存されます。

開発時のみ `window.__game` と `?test=1` による手動シミュレーションが利用できます。本番ビルドでは無効です。

自作の軽量なアーケード車両モデルを採用し、一般的な剛体物理エンジンは使用していません。静的オブジェクトは色・材質別に結合し、木・タイヤ・パーティクルにはInstancedMeshを使用。ピクセル比は1.75に制限しています。開発環境のChromeでは1440×900で約60fpsを確認しましたが、端末のGPUや画面解像度によって変動します。

プレイヤーのフィニッシュ時にレースを確定し、未完走CPUはその時点の進行順で表示します。CPU同士を含む車体同士の剛体衝突、ネット対戦、タッチ操作は現時点の対象外です。
